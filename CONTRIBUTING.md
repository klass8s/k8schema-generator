# Contributing to k8schema-generator

Thank you for helping. This file says what to do before you start, how the generator is organised,
and what a pull request must satisfy to be merged.

## Before you start

- **A bug:** open an issue with the Kubernetes minor and schema patch release, the command you ran,
  and the generated class that is wrong next to what you expected. A bug in a class of k8schema is
  usually a bug here: report it here and mention the k8schema version.
- **A change to the generated code:** open an issue to discuss it before writing the code. Every
  k8schema release is regenerated by this program, so a change here reaches every user of k8schema
  on the next regeneration of each Kubernetes minor.
- **A security issue** is reported privately, never in a public issue: see [SECURITY.md](SECURITY.md).

## How the generator is organised

The application is a Symfony console app (namespace root in `composer.json`, `src/`).

- `src/JsonSchema/` reads the JSON schema into a map of data types (`JsonSchemaService`, `TypesMap`,
  the factories under `DataType/Factory/`).
- `src/Codegen/` turns the types into PHP classes: `K8SCodeGenerationService` drives the run,
  the generators under `Generator/` write API classes, nested data classes and the `*List` and
  `*Map` collections, the resolvers under `TypeResolver/` map a JSON type to a PHP type, and the
  processors under `Processor/Property/` adjust properties before and after they are generated.
  Classes are written with `nette/php-generator`.
- `src/App/` holds the console commands, the event subscribers that shape the output
  (`EventSubscriber/`: the `API_VERSION` and `KIND` constants, the list classes, the fluent getters,
  …), the GitHub and Kubernetes version lookups, and the DI tags under `DependencyInjection/` that
  wire every factory, resolver and processor by its interface.

Most changes to the output are an event subscriber or a property processor rather than a change to a
generator.

## Building and checking

You need PHP 8.5 and Composer.

```bash
composer install
composer install -d tools/php-cs-fixer   # the code-style tool, pinned by its own lock
composer cs:check                        # the code-style check; `composer cs` fixes what it reports
```

The repository has no test suite yet. Check a change by generating the minors it affects before and
after it and reading the diff:

```bash
bin/k8schema-generator schema:fetch v1.35 var/v1.35.json
bin/k8schema-generator generate var/v1.35.json --namespace-prefix='K8Schema' --output-dir=var/out/src
```

A change that deletes generated files or properties is a breaking change for k8schema and says so.

## What a pull request must satisfy

- It targets `main`, never the branch of another open pull request. A change that depends on an
  unmerged one goes into the same pull request, or waits for that one to merge.
- `composer cs:check` passes.
- The description says what the change does to the generated code, with an excerpt of the diff for
  at least one Kubernetes minor.
- The title is a [Conventional Commits](https://www.conventionalcommits.org) header,
  `type(scope): subject`, with `!` after the type for a change that removes or renames generated
  classes or members. Pull requests are squash-merged, so the title becomes the commit on `main`.
  Every commit in the pull request is a Conventional Commit too, with a body that says what changed
  and why.
